3. Architecture & Coding Style Details

🏗️ Clean Architecture (Multilevel Design)

Aapke backend ko bilkul enterprise-grade standards par design kiya gaya hai. Har flow 4 layers se gujarta hai:

  • 1. API Controllers (ApiHost): Ye sirf HTTP requests (GET, POST) lete hain, validation karte hain, aur kaam aage badha dete hain. Yahan koi complex business logic nahi likha gaya hai.
  • 2. BL (Business Logic Layer) & IBL: Yahan system ka asli dimag hai. Tax calculate karna, stock check karna, permissions verify karna—sab yahan hota hai. Is layer ko DB se seedha matlab nahi hai, ye sirf BO (Business Objects) mein deal karta hai.
  • 3. DAC (Data Access Component) & IDAC: Ye layer database (PostgreSQL) se communicate karti hai using EF Core. Iska kaam BL se data (BO) lekar usko Entity mein badal kar DB mein save karna aur nikalna hai.
  • 4. BO & Entities: Entities wo class hain jo direct Database tables (schema) ko map karti hain. BO wo class hain jo ek layer se dusri layer tak data transport karti hain. Inhe alag rakhne se DB schema change karne par baaki app crash nahi hoti.

⚡ Coding Best Practices Used

  • 100% Async / Await: Har database call, har API endpoint async Task aur await ke sath likha gaya hai. Sath hi CancellationToken pas kiya gaya hai. Isse system hang nahi hota, chahe 1000 users ek sath kyu na login karein.
  • Dependency Injection (DI): Interfaces (IProductBL, IProductDAC) ko Dependency Injection ke through connect kiya gaya hai. Isse code highly testable ban jata hai.
  • Global Query Filters (Multi-tenancy): EF Core mein Global Query Filters set kiye gaye hain. Ek store ya tenant kabhi bhi galti se dusre tenant ka data nahi dekh sakta, kyunki query database level par hi filter ho jati hai.
  • Global Exception Handling: Code ke andar chote-chote try-catch lagane ki jagah ek Centralized Error Handler (Middleware) banaya gaya hai. Agar koi error aata hai, toh API automatically ek clean Error JSON (400, 401, ya 500 status code) return karti hai, frontend app crash nahi hota.
